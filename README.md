# Норма

Веб-инструмент для проверки и бережного исправления оформления учебных работ `.docx`. React + TypeScript, статический сайт без backend, учётных записей и платных API. Документы обрабатываются на устройстве пользователя в отдельном Web Worker. Шрифты и все зависимости поставляются с приложением; запросов к CDN, аналитике или внешним API нет.

## Запуск

Нужен Node.js 22.12+ (проверено на Node.js 24).

```sh
npm ci
npm run dev
```

Для production:

```sh
npm run build
npm run preview
```

Публикуйте содержимое `dist/` на любом статическом хостинге с HTTPS. Отдельные сервер, база данных, ключи API и переменные окружения не нужны. Файл `public/_headers` задаёт защитные HTTP-заголовки для хостингов, поддерживающих этот формат (например, Netlify/Cloudflare Pages); на другом сервере настройте эквивалентные заголовки средствами хостинга. Сервер разработки предназначен для локальной работы.

## Архитектура

- `src/document/` — разбор OOXML, профиль, обнаружение нарушений и точечная трансформация. Не зависит от React и DOM браузера.
- `src/workers/document.worker.ts` — изолирует работу с архивом/XML от основного потока.
- `src/lib/document-client.ts` — жизненный цикл Worker, передача буферов, отмена и таймаут; освобождает Worker после каждой операции.
- `src/App.tsx`, `src/App.css` — единый сценарий загрузки, отчёта, выбора исправлений и скачивания.
- `src/sample.ts` — настоящий пример DOCX, создаваемый локально для проверки сервиса.
- `tests/` — документы с нарушениями и regression tests; `e2e/` — сценарии в настоящем Chromium.

Правила и профиль отделены от интерфейса. Начальный профиль — типовое оформление: Times New Roman 14 pt, интервал 1.5, по ширине, отступ 1.25 см, поля слева 3 см, справа 1.5 см, сверху и снизу 2 см. Это общий профиль, а не подтверждение соответствия требованиям конкретного вуза или всем положениям ГОСТ. Его можно изменить перед анализом.

## Безопасность документов

Исходный файл не перезаписывается. Исправления создают новый ZIP/DOCX и затрагивают только свойства оформления основного документа; остальные части архива сохраняются. Заголовки, таблицы, подписи, формулы, поля и сложные структуры требуют осторожной обработки. Приложение не пытается восстановить повреждённый документ или угадать его смысловую структуру. Подробные ограничения приведены в отчёте и интерфейсе.

Проверка — структурная, без визуального движка Word: приложение не вычисляет количество страниц и не обещает неизменность разбиения на страницы после изменения шрифтов или полей. Шрифт должен быть установлен на устройстве, где документ открывается. Перед сдачей просмотрите результат в Word или LibreOffice.

В браузере сохраняются настройки профиля и ограниченная история метаданных, но не файлы, их содержимое и исправленные копии. Историю можно очистить. Документ остаётся в оперативной памяти только на время текущей сессии; новая загрузка, сброс или закрытие страницы освобождает ссылку на него. Предел размера загрузки — 20 МиБ; обработчик дополнительно проверяет размеры распаковки и структуру архива.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

E2E используют системный Chromium по пути `/usr/bin/chromium`, если он доступен. На другой машине выполните `npx playwright install chromium` или задайте `CHROMIUM_PATH=/путь/к/chromium`. Браузерные тесты запускают dev-сервер автоматически. Они не требуют внешнего сервиса. В `.github/workflows/checks.yml` добавлены сборка, regression tests и E2E для GitHub Actions.

Для разработки используйте существующий checkout: облачная задача уже изолирована, создавать дополнительный Git worktree не требуется.
